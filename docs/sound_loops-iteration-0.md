# sound_loops — итерация 0: каркас и случайный саундтрек

## Контекст

Пет-проект: подбор музыки к немым коротким видео-лупам. Финальная цель, до которой мы дойдём за несколько итераций, — агент, который анализирует видео и подбирает подходящий трек по смыслу и настроению.

Итерация 0 строит только транспорт: из базы берутся луп и отрезок трека, ffmpeg склеивает превью. Музыка выбирается случайно — это осознанный baseline, с которым будут сравниваться следующие версии.

Объём работ ограничен этой итерацией.

Железо: MacBook M3 Pro, 18 ГБ. Python 3.12.

## Цель

CLI, который собирает mp4: немой луп плюс случайный отрезок случайного трека, подрезанный под длительность этого лупа. Факт рендера сохраняется в базе.

## Definition of Done

1. Схема создаётся в существующей базе; повторный запуск не падает.
2. Ингест заполняет таблицы лупов, треков и их отрезков; повторный запуск не создаёт дубликатов.
3. Рендер десять раз подряд выдаёт mp4, которые открываются в QuickTime со звуком, и длительность каждого совпадает с длительностью исходного лупа.
4. В таблице рендеров появились соответствующие записи.
5. Линтер и тесты проходят.

## Окружение

PostgreSQL уже установлен и запущен локально — ставить не нужно, использовать существующий инстанс и создать в нём отдельную базу. Строка подключения берётся из `.env`, в репозитории лежит `.env.example`.

Остальное: ffmpeg, uv, Python 3.12. Зависимости — только те, что нужны итерации: CLI, драйвер Postgres, валидация конфига, линтер и тесты.

## Данные

`data/` целиком в `.gitignore`.

**Лупы** — готовые mp4 в `data/loops/`. Готовятся вручную вне проекта: длительность от 3 до 10 секунд, без аудиодорожки. Код их не создаёт и не изменяет, только сканирует и читает метаданные. Файл, который не подходит под эти условия, логируется и пропускается — весь прогон из-за него падать не должен.

**Музыка** — датасет FMA (Free Music Archive), выкладка легально распространяемой музыки, которую поддерживает лаборатория EPFL. (cite index="4-2">Подмножество `fma_small` — это 8 000 тридцатисекундных отрывков в mp3, по 8 сбалансированным жанрам, 7,2 ГиБ</cite>. Метаданные лежат отдельно: (cite index="4-3">архив `fma_metadata.zip` (342 МиБ), где `tracks.csv` содержит название, исполнителя, жанры и теги для всех 106 574 треков</cite>.

Перед скачиванием треков и мета оценить сколько понадобится диска.

Ожидаемая раскладка после распаковки: `data/raw/fma_small/000/000002.mp3`, то есть mp3 разложены по трёхзначным подпапкам, а имя файла — шестизначный ID трека. По этому ID строка находится в `tracks.csv`. Сканировать директорию нужно рекурсивно.

У `tracks.csv` многоуровневый заголовок в несколько строк — читать его стандартным csv-модулем неудобно. Метаданные не критичны для итерации 0: если разбор оказывается муторным, поля названия, исполнителя и жанра остаются пустыми, и это не ошибка.

Для итерации 0 хватит любых 200–300 mp3, так что можно распаковать только несколько подпапок.

## Модель данных

Четыре сущности:

- **лупы** — путь, длительность, разрешение;
- **треки** — путь, длительность, метаданные из датасета;
- **отрезки треков** — координаты внутри трека (начало и длительность), а не файлы на диске; нарезаются по сетке при ингесте;
- **рендеры** — какой луп с каким отрезком склеен и куда сохранён.

Путь — естественный ключ уникальности для лупов и треков, ингест на нём идемпотентен.

## Что должен уметь код

**Ингест.** Обойти директории с лупами и музыкой, вытащить метаданные через ffprobe, разложить по таблицам, нарезать треки на отрезки. В конце напечатать, сколько добавлено и сколько пропущено с причинами.

**Рендер.** Взять луп (по пути или случайный), взять случайный отрезок трека, вырезать из него аудио ровно под длительность лупа, склеить с видео без перекодирования видеопотока, сохранить результат и запись в базу, вывести путь.

Два требования к качеству склейки, которые легко упустить:

- на краях вырезанного аудио нужны короткие фейды, иначе каждое превью начинается и заканчивается щелчком и звучит как брак независимо от того, насколько удачна музыка;
- длительность результата определяется видео: если отрезок аудио длиннее лупа, лишнее обрезается.

С ffmpeg и ffprobe работать через subprocess, без питоновских обёрток поверх — команда должна оставаться читаемой и копируемой в терминал. Ошибки бинарей пробрасывать с содержательным сообщением, а не с голым кодом возврата.


## Тесты

Немного и по существу: вырезанное аудио имеет ожидаемую длительность, склеенный файл содержит оба потока, сетка отрезков считается верно для треков разной длины.
