# sound_loops

Пет-проект: подбор музыки к немым коротким видео-лупам. Итерация 0 строит
только транспорт — из базы берётся луп и отрезок трека, ffmpeg склеивает
превью в mp4. **Музыка выбирается случайно.** Это осознанный baseline: он
не пытается быть «умным» и служит точкой сравнения для следующих итераций,
где выбор музыки будет опираться на анализ видео.

## Что нужно установить

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- ffmpeg / ffprobe (например, `brew install ffmpeg`)
- PostgreSQL — предполагается, что локальный инстанс уже установлен и
  запущен; проект создаёт в нём отдельную базу, устанавливать PostgreSQL
  не нужно.

Установить зависимости проекта:

```bash
make sync
```

## Как поднять базу

Скопировать `.env.example` в `.env` и указать строку подключения к уже
работающему локальному Postgres:

```bash
cp .env.example .env
```

Создать базу и схему (идемпотентно — повторный запуск не падает):

```bash
make init-db
```

## Куда класть лупы и музыку

Всё содержимое `data/` в `.gitignore` — эти файлы не попадают в репозиторий.

- **Лупы** — готовые mp4 в `data/loops/` (можно вложенно). Готовятся
  вручную вне проекта: 3–10 секунд, без аудиодорожки. Код их не создаёт и
  не изменяет, только сканирует и читает метаданные через ffprobe. Файл,
  который не подходит под эти условия (не читается, с аудио, не в
  диапазоне длительности), логируется и пропускается — прогон из-за него
  не падает.

- **Музыка** — подмножество `fma_small` датасета [FMA (Free Music
  Archive)](https://github.com/mdeff/fma): 8000 тридцатисекундных mp3.
  Ожидаемая раскладка после распаковки:
  `data/raw/fma_small/000/000002.mp3` — mp3 разложены по трёхзначным
  подпапкам, имя файла — шестизначный ID трека. Метаданные — отдельно,
  `data/raw/fma_metadata/tracks.csv`. Для итерации 0 достаточно 200–300
  mp3, распаковывать весь архив (7+ ГиБ) не обязательно — можно взять
  несколько подпапок.

  Перед скачиванием стоит прикинуть место на диске: `fma_small.zip` — это
  ~7,2 ГиБ, `fma_metadata.zip` — ~342 МиБ. Если нужны не все файлы,
  оба архива поддерживают HTTP Range-запросы, и нужную часть можно
  скачать без загрузки архива целиком.

## Команды

```bash
make sync      # установить зависимости проекта
make init-db   # создать базу и схему (идемпотентно)
make ingest    # просканировать data/loops и data/raw,
               # заполнить таблицы, напечатать статистику
make render    # случайный луп + случайный отрезок трека -> data/renders/*.mp4
make render-loop LOOP=data/loops/my_loop.mp4  # рендер для конкретного лупа
make test      # прогнать тесты
make lint      # прогнать линтер
make clean     # удалить .venv и кэши тестов/линтера
```

Каждая цель — тонкая обёртка над `uv run sound-loops ...` (см. `Makefile`).

`render` печатает путь к получившемуся файлу и сохраняет запись о рендере
в базу.

## Модель данных

- **loops** — путь, длительность, разрешение.
- **tracks** — путь, длительность, метаданные из датасета (название,
  исполнитель, жанр — могут быть пустыми, если разбор `tracks.csv` не
  удался; это не ошибка).
- **track_segments** — координаты внутри трека (начало и длительность),
  а не файлы на диске; нарезаются по сетке при ингесте.
- **renders** — какой луп с каким отрезком склеен и куда сохранён.

Путь — естественный ключ уникальности для лупов и треков: повторный
запуск `ingest` обновляет существующие строки, а не создаёт дубликаты.

## Как собирается превью

Аудио вырезается из случайного отрезка трека ровно под длительность лупа,
с короткими фейдами на входе и выходе (иначе на срезе слышен щелчок).
Видеопоток не перекодируется — луп подшивается как есть, а итоговую
длительность определяет видео: если аудио оказалось длиннее, лишнее
обрезается. С ffmpeg/ffprobe работа идёт через subprocess плоскими
списками аргументов — команду легко скопировать и повторить в терминале.

## Тесты и линтер

Тесты не требуют базы, реальных лупов или датасета — для проверки
`ffmpeg`-склейки используются синтетические видео/аудио, сгенерированные
самим ffmpeg (`lavfi`). Проверяется: длительность вырезанного аудио,
наличие обоих потоков в склеенном файле, и что сетка отрезков считается
верно для треков разной длины.
