# sound_loops

Пет-проект: подбор музыки к немым коротким видео-лупам. Итерация 0 построила
транспорт — из базы берётся луп и отрезок трека, ffmpeg склеивает превью в
mp4, музыка выбирается случайно. Итерация 1 добавляет смысл: треки
превращаются в эмбеддинги через [CLAP](https://github.com/LAION-AI/CLAP), и
текстовый запрос вроде «sad piano» можно сравнивать напрямую с аудио через
[pgvector](https://github.com/pgvector/pgvector).

## Что нужно установить

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- ffmpeg / ffprobe (например, `brew install ffmpeg`)
- PostgreSQL — предполагается, что локальный инстанс уже установлен и
  запущен; проект создаёт в нём отдельную базу, устанавливать PostgreSQL
  не нужно.
- Расширение [pgvector](https://github.com/pgvector/pgvector) для этого
  инстанса Postgres. Готового бинарного пакета под все версии Postgres в
  brew может не быть (например, для `postgresql@15` есть бандлы только под
  17/18) — тогда собрать из исходников под свою версию:

  ```bash
  git clone --depth 1 --branch v0.8.0 https://github.com/pgvector/pgvector.git
  cd pgvector
  make PG_CONFIG=$(brew --prefix postgresql@15)/bin/pg_config
  make install PG_CONFIG=$(brew --prefix postgresql@15)/bin/pg_config
  ```

  (замените `postgresql@15` на свою версию). `make init-db` сам делает
  `CREATE EXTENSION vector` в миграции — собрать расширение нужно один раз
  заранее, руками ничего создавать не надо.

Установить зависимости проекта:

```bash
make sync
```

## Как поднять базу

Скопировать `.env.example` в `.env` и указать строку подключения к уже
работающему локальному Postgres:

```bash
cp .env.example .env
```

Создать базу и накатить миграции (идемпотентно — повторный запуск не
падает и не применяет уже применённые миграции повторно):

```bash
make init-db
```

Схема управляется через [yoyo](https://ollycope.com/software/yoyo/latest/)
— миграции лежат в `src/sound_loops/migrations/`, каждая пронумерована и
применяется ровно один раз, факт применения yoyo фиксирует сам (таблицы
`_yoyo_*`). Новое изменение схемы — это новый файл в этой папке, а не
правка существующего.

## Куда класть лупы и музыку

Всё содержимое `data/` в `.gitignore` — эти файлы не попадают в репозиторий.

- **Лупы** — готовые mp4 в `data/loops/` (можно вложенно). Готовятся
  вручную вне проекта: 3–10 секунд, без аудиодорожки. Код их не создаёт и
  не изменяет, только сканирует и читает метаданные через ffprobe. Файл,
  который не подходит под эти условия (не читается, с аудио, не в
  диапазоне длительности), логируется и пропускается — прогон из-за него
  не падает.

- **Музыка** — подмножество `fma_small` датасета [FMA (Free Music
  Archive)](https://github.com/mdeff/fma): 8000 тридцатисекундных mp3.
  Ожидаемая раскладка после распаковки:
  `data/raw/fma_small/000/000002.mp3` — mp3 разложены по трёхзначным
  подпапкам, имя файла — шестизначный ID трека. Метаданные — отдельно,
  `data/raw/fma_metadata/tracks.csv`. Для итерации 0 достаточно 200–300
  mp3, распаковывать весь архив (7+ ГиБ) не обязательно — можно взять
  несколько подпапок.

  Перед скачиванием стоит прикинуть место на диске: `fma_small.zip` — это
  ~7,2 ГиБ, `fma_metadata.zip` — ~342 МиБ. Если нужны не все файлы,
  оба архива поддерживают HTTP Range-запросы, и нужную часть можно
  скачать без загрузки архива целиком.

## Команды

```bash
make sync      # установить зависимости проекта
make init-db   # создать базу и схему (идемпотентно)
make ingest    # просканировать data/loops и data/raw,
               # заполнить таблицы, напечатать статистику
make render    # случайный луп + случайный отрезок трека -> data/renders/*.mp4
make render-loop LOOP=data/loops/my_loop.mp4  # рендер для конкретного лупа
make index     # посчитать эмбеддинги треков, у которых их ещё нет (CLAP)
make search QUERY="sad piano"                      # найти и напечатать топ-5
make search QUERY="sad piano" EXPORT=data/found     # + скопировать в data/found для прослушивания
make clap-check  # проверка вменяемости: текстовая башня CLAP не схлопнута
make test      # прогнать тесты
make lint      # прогнать линтер
make clean     # удалить .venv и кэши тестов/линтера
```

Каждая цель — тонкая обёртка над `uv run sound-loops ...` (см. `Makefile`).

`render` печатает путь к получившемуся файлу и сохраняет запись о рендере
в базу. `index`/`search` — см. раздел «Поиск музыки по тексту» ниже.

## Модель данных

- **loops** — путь, длительность, разрешение.
- **tracks** — путь, длительность, метаданные из датасета (название,
  исполнитель, жанр — могут быть пустыми, если разбор `tracks.csv` не
  удался; это не ошибка), и с итерации 1 — `embedding` (`vector(512)`,
  HNSW-индекс по косинусной метрике) и `embedding_model` (какой чекпоинт
  его посчитал). Отдельной таблицы под эмбеддинги нет: у трека их ровно
  один на актуальную модель, `embedding_model` нужен только чтобы при
  смене чекпоинта было видно, что в колонке лежит устаревшее значение —
  `index` пересчитает такие треки заново.
- **renders** — какой луп с каким треком склеен, координаты вырезанного
  отрезка (`track_id`, `start_seconds`) и куда сохранён результат.
  Отдельной таблицы под отрезки нет: координаты вычисляются на лету при
  рендере и используются ровно один раз, так что хранить их отдельно от
  самого факта рендера незачем.

Путь — естественный ключ уникальности для лупов и треков: повторный
запуск `ingest` обновляет существующие строки, а не создаёт дубликаты.

## Как собирается превью

При рендере выбирается случайный трек, которого хватит на длительность
лупа, и внутри него — случайная точка начала (без привязки к какой-либо
сетке). Аудио вырезается ровно под длительность лупа, с короткими
фейдами на входе и выходе (иначе на срезе слышен щелчок). Видеопоток не
перекодируется — луп подшивается как есть, а итоговую длительность
определяет видео: если аудио оказалось длиннее, лишнее обрезается.
С ffmpeg/ffprobe работа идёт через subprocess плоскими списками
аргументов — команду легко скопировать и повторить в терминале.

## Поиск музыки по тексту

Треки превращаются в эмбеддинги через [CLAP](https://github.com/LAION-AI/CLAP)
(`transformers.ClapModel`/`ClapProcessor`. Чекпоинт — **`laion/larger_clap_general`**.
Устройство по умолчанию — MPS, при ошибке автоматически
откатывается на CPU (`CLAP_DEVICE` в `.env`, если нужно зафиксировать CPU
сразу). Первый запуск качает веса с HuggingFace Hub; дальше, если чекпоинт
уже в `~/.cache/huggingface`, каждый последующий `index`/`search`/`clap-check`
работает полностью офлайн — `hf_cache.py` сам выставляет `HF_HUB_OFFLINE=1`
(иначе `transformers` на каждый запуск лишний раз стучится в сеть сверяться
с последней ревизией репозитория, даже когда веса уже скачаны).

```bash
make index                                        # посчитать эмбеддинги новых/непроиндексированных треков
make search QUERY="sad piano"                     # топ-5 в терминал: похожесть, название, путь
make search QUERY="sad piano" EXPORT=data/found    # + скопировать в data/found для прослушивания
make clap-check                                    # проверка вменяемости: текстовая башня не схлопнута
```

`index` берёт из `tracks` записи без эмбеддинга **или** с эмбеддингом от
другого чекпоинта (`embedding_model` хранит, какой именно), декодирует
аудио через ffmpeg (`-f f32le` на stdout), считает эмбеддинги батчами и
коммитит после каждого батча — если процесс прервать, уже посчитанное не
теряется, а следующий запуск подхватит только оставшееся.

`search` считает эмбеддинг запроса, ищет ближайшие по косинусной близости
через HNSW-индекс (`embedding <=> ...`, `pgvector`) и печатает похожесть
вместе с путём к файлу — но по цифрам «грустное» от «эпичного» не отличить,
поэтому `--export-dir`/`EXPORT=` существуют специально для прослушивания.

**Проверка вменяемости** (см. `docs/sound_loops-iteration-1.md`): `clap-check`
считает попарные косинусные близости нескольких заведомо непохожих фраз —
если все около 0.99, текстовая башня схлопнута и чекпоинт непригоден. На
чекпоинте `laion/larger_clap_general` они лежат в диапазоне 0.06–0.27 —
башня не схлопнута.

Вторая часть — ручная: прогнать контрастные запросы и послушать топ-N через
`EXPORT=`. По итогам прослушивания на `fma_small` (268 треков): **выдача
осмысленна** — на запросы вроде «sad slow piano» / «fast aggressive
electronic dance music» / «female operatic vocal» модель уверенно подбирает
релевантные по настроению и инструментовке треки, топ выдачи для разных
контрастных запросов не пересекается.

## Тесты и линтер

```bash
make test
make lint
```

Тесты используют настоящий Postgres — отдельную базу `<имя_рабочей_базы>_test`
в том же локальном инстансе, что и рабочая (та же строка подключения из
`.env`, только имя базы с суффиксом `_test`). База и схема создаются
автоматически при первом запуске тестов; перед каждым тестом, которому
нужна база, все таблицы очищаются — тесты не зависят друг от друга и от
состояния рабочей базы.

Реальных лупов и датасета не требуется — видео и аудио для тестов
генерируются самим ffmpeg (`lavfi`). Каждая уникальная пара (тип,
длительность) кодируется один раз за сессию pytest и кэшируется —
тесту, которому нужен файл под своим именем/путём, отдаётся копия
закэшированного файла, а не свежий энкод (см. `get_silent_loop`/
`get_tone_track` в `conftest.py`). Проверяется: длительность вырезанного
аудио и наличие обоих потоков в склеенном файле, что случайная точка
начала отрезка всегда попадает в допустимые границы трека, разбор
`tracks.csv` (в том числе отсутствующий/битый файл), валидация конфига,
идемпотентность `init-db` и `ingest`, и что `render`, повторённый
несколько раз подряд, каждый раз создаёт ровно одну новую строку в
`renders`.
